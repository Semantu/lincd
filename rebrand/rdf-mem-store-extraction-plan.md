# @_linked/rdf-mem-store — extraction plan

## Context

This package provides the in-memory RDF models and store implementation that can execute query objects generated by `@_linked/core`.

Work on this was already started in **branch `origin/codex/implement-additional-query-tests-in-linked-js`** under `rebrand/linked-mem-store`. That version depends on the older `linked-js` package (no query result types) and must be updated to use `@_linked/core`.

The goal now is to port that work forward, align it with the new core package, and validate execution using the shared query fixtures from core.

## Key constraints

- `@_linked/core` is the source of truth for query object shapes and type inference.
- `NamedNode` and RDF models belong in this package (not in core).
- Use the shared query fixtures from `@_linked/core/src/test-helpers/query-fixtures.ts`.
- The store must implement `IQuadStore` from core and be configurable through `LinkedStorage`.
- Prefer local linking via workspaces or `npm link` for development.

## Phase 0 — Baseline import

- Copy `rebrand/linked-mem-store` from `origin/codex/implement-additional-query-tests-in-linked-js` into `rebrand/rdf-mem-store`.
- Rename package to `@_linked/rdf-mem-store`.
- Update package entry points (`package.json`, exports, build/test scripts).

## Phase 1 — Align dependencies & imports

- Replace all `linked-js/*` imports with `@_linked/core/*`.
- Update any query types to use core (`SelectQuery`, `CreateQuery`, `UpdateQuery`, `DeleteQuery`).
- Update `LinkedStorage` usage to core API.
- Ensure `IQuadStore` matches core.

## Phase 2 — NodeReferenceValue interop

- Accept `NodeReferenceValue` anywhere core expects it.
- Ensure `NamedNode` instances can still be used internally, but results must be compatible with `NodeReferenceValue`/`QResult` objects.
- Update ontology helpers to return `NodeReferenceValue` where used by core fixtures.

## Phase 3 — Store resolution logic

- Align `LocalQueryResolver` (or equivalent) with core query object shape.
- Confirm create/update/delete use the new core mutation shapes.
- Keep legacy quad-level APIs optional (deprecated).

## Phase 4 — Tests (execute queries, validate results)

- Import shared query factories from core (`@_linked/core/src/test-helpers/query-fixtures`).
- Port existing memstore tests to run against the real InMemoryStore and validate actual results (mirroring old `src/tests/query.test.ts` logic).
- Add tests for mutations (create/update/delete) using core update shapes (including add/remove set updates).

## Phase 5 — Final verification

- Ensure all tests pass.
- Ensure type inference flows from core into memstore usage.
- Document any remaining gaps or TODOs.
